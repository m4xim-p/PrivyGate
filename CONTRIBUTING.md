# Участие в разработке PrivyGate

## Перед началом

1. Прочитайте `AGENTS.md`, `docs/source/README.md`, нормативные Приложения A/B,
   сохранённые уточнения организаторов, обязательный `SECURITY.md` и
   `docs/evaluation-contract.md`.
2. Проверьте `git status`: незакоммиченные изменения могут принадлежать другому инженеру.
3. Найдите существующий detector, service или policy, который следует расширить.
4. Для архитектурного изменения создайте или обновите ADR в `docs/adr/`.
5. Помните, что `POST /process` — обязательный внешний контракт: внутренний
   рефакторинг не должен менять его schema и state semantics.

## Координация команды

- Перед началом зафиксируйте задачу, ответственного и ожидаемые файлы в общем task board
  или командном чате.
- У одного hotspot-файла в конкретный момент должен быть один активный владелец.
- Для `app/pii.py`, `app/main.py`, `docker-compose.yml` и contract models обязательно
  согласуйте пересечение до начала правок.
- Независимые задачи можно выполнять параллельно; запрет относится к несогласованному
  редактированию одного hotspot, а не к параллельной работе вообще.
- Перед merge обновитесь от актуального `main` и повторно проверьте diff: не включайте
  чужие незавершённые изменения в свой PR.

## Принципы работы

- Один PR решает одну связанную задачу и не содержит постороннего рефакторинга.
- Endpoint остаётся тонким адаптером; PII-логика размещается в общем domain layer.
- Новый detector реализует `PIIDetector` и возвращает `PIIMatch`.
- Не копируйте masking/demasking logic между `/process` и LLM proxy.
- Не добавляйте runtime-зависимости без описания пользы, стоимости и альтернатив.
- Не используйте реальные персональные данные в коде, fixtures, документации и логах.
- Не добавляйте format-preserving mask только для AlfaSonar: scorer принимает любые
  replacement symbols и оценивает исходные PII spans.
- Держите функции и модули небольшими; автоматическая проверка анализирует complexity,
  DRY/KISS, conventions и deprecated APIs.

## Тестирование

Минимум для каждого detector:

- корректный пример;
- некорректный или отрицательный контекст;
- варианты регистра и формата;
- сохранение offsets;
- конфликт с другим detector;
- masking/demasking round-trip.

Запуск тестов:

```bash
python -m pytest -q
```

Реальная NER-модель в unit-тестах не загружается. Для NER используется fake backend.
Performance-изменение должно сопровождаться командой запуска benchmark и результатами
p50/p95/p99, RPS, error rate и размером входа.

## Definition of Done

- Код использует существующие точки расширения и не создаёт параллельную реализацию.
- Релевантные и полные тесты проходят.
- Raw PII отсутствует в production logs и metrics.
- Статус требования обновлён в `docs/requirements.md`.
- Публичное поведение и ограничения описаны в README или профильном документе.
- Для архитектурного решения обновлён ADR.

Перед commit/PR пройдите checklist из `SECURITY.md`. Для изменений `/process`
дополнительно подтвердите: публичный вызов без auth headers не получает `403`, retries
идемпотентны, store имеет entry/byte bounds, а payload и mapping отсутствуют в логах.
