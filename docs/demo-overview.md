# PrivyGate — что реализовано (обзор для команды)

Краткий обзор бизнес-функционала и фич, которые уже готовы. Используется для
демо и рассказа команде о текущем состоянии продукта.

---

## Что это

**PrivyGate** — модуль безопасности персональных данных (PII). Он встраивается в
цепочку «система-потребитель → Модуль → LLM» и защищает персональные данные при
обращении к языковым моделям:

1. **Идентифицирует** персональные данные (ФИО, паспорт, телефон, email, карты и т.д.).
2. **Маскирует** их перед отправкой в LLM.
3. **Демаскирует** ответ, если это разрешено политикой системы.

---

## Реализованный функционал

### 1. Детекция персональных данных (17 обязательных категорий)

Распознаются все типы ПДН из ТЗ:

| Категория | Пример |
|---|---|
| ФИО | Иванов Иван Иванович |
| Дата рождения | 01.01.1990 |
| Место рождения | г. Москва |
| Паспорт РФ | 45 10 123456 |
| Гражданство | Российская Федерация |
| Орган выдачи | УФМС России |
| Код подразделения | 770-001 |
| Дата выдачи | 01.01.2010 |
| Водительское удостоверение | 77 01 123456 |
| Адрес | г. Москва, ул. Тестовая, д. 1 |
| Email | user@example.com |
| Телефон | +7 900 000 00 00 |
| ИНН | 770708389301 |
| Номер карты | 4000 0000 0000 0000 |
| CVV | 000 |
| PIN | 0000 |
| Имя держателя карты | IVANOV IVAN |

Дополнительно: **СНИЛС** (с checksum), **зарубежные паспорта**, **военный билет**.

**Гибридная детекция:** rule-based (regex + checksum) для структурированных типов
+ опциональный локальный NER для ФИО в сложных предложениях.

### 2. Маскирование (3 режима)

| Режим | Пример |
|---|---|
| `typed_placeholder` (по умолчанию) | `__PII_PERSON_1__` |
| `synthetic` (синтетика) | `Иванов Иван Иванович` |
| `format_preserving` (сохранение формата) | `**** *****` |

### 3. Демаскирование

- Восстановление исходного текста по mapping.
- Работает для `/process` (возврат сохранённого original) и для streaming-ответа LLM.

### 4. Контракт `/process` (автопроверка AlfaSonar)

- `POST /process` — маскирование/демаскирование, корреляция по `payload_id`.
- Idempotency, retries, 409/410/413/422/429.
- Логирование типов ПДН по каждому запросу (без raw PII).

### 5. Политики потребителей (per-consumer настройка)

Каждая система-потребитель настраивается через JSON-конфиг:

- **Вкл/откл** обращения в модуль.
- **Перечень типов ПДН** для маскирования (`enabled_pii_types`).
- **Исключения** (`excluded_pii_types`) — «маскировать всё, кроме X».
- **Право демаскирования** (`allow_demasking`).
- **Вид маскирования** (`masking_mode`).
- **Порог уверенности** (`min_confidence`).
- **Поведение при сбое** (`degradation`: fail_closed / rule_only).

**Allowlist:** продуктовый API защищён API-ключами (`X-Consumer-ID` + `Authorization`).
`/process` (автопроверка) работает без auth.

### 6. Надёжность

- **Fail-closed:** при недоступности детектора возвращается 5xx, а не raw текст.
- **Degradation rule_only:** при сбое NER продолжается rule-based маскирование.
- **Offline NER:** модель скачивается при сборке docker-образа, в runtime грузится
  локально (без сети).

### 7. Безопасность

- Raw PII, prompt и mapping **не логируются**.
- Логируются только типы ПДН, количество, latency, status.
- Локальный NER не отправляет данные во внешние сервисы.

### 8. Производительность

- k6 load test для `/process` (`scripts/k6/process_load.js`) + real-time metrics
  collector (`scripts/k6/metrics_collector.py`, `run_benchmark.sh`).
- Полный 5-минутный прогон: **hold-фаза ~999.5 HTTP RPS**, mask p95 9ms,
  dropped_iterations ~0 на hold, 0 ошибок/retries/429.
- CPU-профилирование (py-spy): bottleneck `ProcessStore` eviction устранён
  (ADR-0006, min-heap индекс истечения) — ProcessStore 78.77% → 0.70% активного
  CPU, event loop delay 0ms.
- Обработка текстов до 100 000 токенов (валидация лимита).

### 9. Качество

- Строгий entity/span harness (`tests/quality_harness.py`).
- Golden datasets: golden F1 0.934, api F1 0.843, extended F1 0.912, variants
  F1 0.937.
- Ratchet-тесты не дают качеству регрессировать.

### 10. Инженерная гигиена

- Merge-blocking gate: Ruff, mypy, Bandit, pip-audit, pytest.
- ADR для архитектурных решений (0001-0006).
- README с примерами запросов и настройки.

## Примеры использования

### Пример 1: система видит email, остальное скрыто

```json
{
  "consumer_id": "email-agent",
  "enabled": true,
  "excluded_pii_types": ["EMAIL"],
  "allow_demasking": true,
  "api_keys": ["CHANGE_ME_email_agent_api_key"]
}
```

Оператор видит почту клиента (чтобы ответить), но не видит телефон/паспорт/ФИО.

### Пример 2: система маскирует только паспорт

```json
{
  "consumer_id": "passport-only",
  "enabled": true,
  "enabled_pii_types": ["PASSPORT"],
  "allow_demasking": true,
  "api_keys": ["CHANGE_ME_passport_api_key"]
}
```

### Пример 3: синтетическое маскирование

```json
{
  "consumer_id": "synthetic-agent",
  "enabled": true,
  "masking_mode": "synthetic",
  "allow_demasking": true,
  "api_keys": ["CHANGE_ME_synthetic_api_key"]
}
```

## Как запустить

```bash
# Локально (rule-based)
uvicorn app.main:app --port 8000

# С NER
NER_ENABLED=true uvicorn app.main:app --port 8000

# Docker Compose
docker compose up --build
```
