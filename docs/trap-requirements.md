# Требования к ловушкам (trap cases)

Ловушки — это негативные кейсы, которые **не должны** маскироваться, но часто
ошибочно распознаются детекторами как PII. Они проверяют критерий 3.3
«Точность отнесения к ПДН и устойчивость к вариациям написания» и критерий
финалистов «Доверие» (не паникует на ловушках).

Источник требований: `docs/source/evaluation-criteria.md` (критерий 3.3),
`docs/source/organizer-clarifications.txt`, `docs/requirements.md`.

## Принципы

- **False negative штрафуется сильнее false positive**, но blanket masking и
  захват служебных слов запрещены.
- Ловушка — это текст, который **похож** на PII, но не является персональными
  данными конкретного лица.
- Ловушка не должна маскироваться, иначе это ложное срабатывание (FP).

## Категории ловушек

### 1. Исторические и публичные личности (PERSON)

Не маскировать имена известных людей, писателей, поэтов, композиторов.

| Пример | Почему не PII |
|--------|---------------|
| «Александр Пушкин» | Историческая личность |
| «Лев Толстой» | Историческая личность |
| «Фёдор Достоевский» | Историческая личность |
| «Антон Чехов» | Историческая личность |
| «Михаил Булгаков» | Историческая личность |
| «Пётр Чайковский» | Композитор |
| «Александр Сергеевич Пушкин» | Полное ФИО исторической личности |

### 2. Адреса организаций и отделений (ADDRESS)

Не маскировать адреса банков, офисов, отделений, пунктов выдачи.

| Пример | Почему не PII |
|--------|---------------|
| «Отделение банка: г. Москва, ул. Тверская, д. 7» | Адрес организации |
| «Банкомат по адресу: ул. Ленина, 10» | Адрес организации |
| «Офис компании: г. Санкт-Петербург, Невский проспект, 28» | Адрес организации |
| «Юридический адрес организации: 123456, г. Москва, ул. Арбат, 5» | Адрес организации |
| «Пункт выдачи: г. Екатеринбург, ул. Малышева, 51» | Адрес организации |

### 3. Корпоративные контакты (PHONE, EMAIL)

Не маскировать общие номера и почты поддержки, горячих линий.

| Пример | Почему не PII |
|--------|---------------|
| «Горячая линия: 8 800 555-35-35» | Общий номер |
| «Служба поддержки +7 495 123-45-67» | Общий номер |
| «Почта поддержки help@bankexample.ru» | Корпоративная почта |

### 4. Номера заказов, артикулы, договоры (PHONE, INN, CARD)

Не маскировать числовые идентификаторы, не являющиеся PII.

| Пример | Почему не PII |
|--------|---------------|
| «Номер заказа 1234567890» | Номер заказа |
| «Артикул 123456789012» | Артикул |
| «Номер договора 1234567890» | Номер договора |
| «Тикет #1234567890» | Тикет |

### 5. Даты, не связанные с рождением (DATE_OF_BIRTH)

Не маскировать даты, не являющиеся датой рождения.

| Пример | Почему не PII |
|--------|---------------|
| «Срок действия до 31.12.2025» | Срок действия |
| «Заседание назначено на 15.03.2024» | Рабочая дата |
| «Стихотворение написано в 1818 году» | Историческая дата |

### 6. Географические объекты без связи с лицом (ADDRESS, BIRTH_PLACE)

Не маскировать города/регионы сами по себе.

| Пример | Почему не PII |
|--------|---------------|
| «Самые крупные города: Москва, Санкт-Петербург» | География |
| «Хочу поехать в Сочи, Казань, Байкал» | География |

### 7. Названия организаций (PERSON)

Не маскировать названия компаний, похожие на ФИО.

| Пример | Почему не PII |
|--------|---------------|
| «Контрагент "Кузбасская Топливная Компания"» | Название ЮЛ |
| «Счёт от "Метро Кэш энд Керри"» | Название ЮЛ |

### 8. Служебные слова (все категории)

Не захватывать служебные слова в маску.

| Пример | Почему не PII |
|--------|---------------|
| «Серия 45 10» (без номера) | Служебное слово |
| «ул.» (без названия) | Служебное слово |
| «года» (без даты) | Служебное слово |
| «дом» (без номера) | Служебное слово |

### 9. Иностранные документы (PASSPORT)

Не маскировать иностранные паспорта (не входят в 17 категорий).

| Пример | Почему не PII |
|--------|---------------|
| «Passport No. 512345678, гражданин Казахстана» | Иностранный документ |

### 10. PIN/CVV без карты (PIN, CVV)

Не маскировать PIN/CVV без номера карты в том же тексте (комбинационное правило).

| Пример | Почему не PII |
|--------|---------------|
| «Старый пин 4321 больше не хочу использовать» | PIN без карты |
| «CVV-код — это три цифры на обороте карты» | CVV без карты |

### 11. Устойчивость к опечаткам и вариациям (positive)

Опечатки в словах рядом с PII **не должны** ломать распознавание самой PII.
Номер карты распознаётся по Luhn независимо от искажения слова «номер».

| Пример | Ожидание |
|--------|----------|
| «ном,ер карты 4111111111111111» | Карта маскируется (опечатка в слове) |
| «онмер карты 4111111111111111» | Карта маскируется (переставлены буквы) |
| «номмер карты 4111111111111111» | Карта маскируется (лишняя буква) |
| «номер   карты 4111111111111111» | Карта маскируется (лишние пробелы) |
| «номер карты  4111111111111111» | Карта маскируется (лишние пробелы перед номером) |

### 12. Смешанные русские/английские написания (positive)

PIN на английском (разный регистр) маскируется только с картой (комбинационное
правило), как и русский «пин-код».

| Пример | Ожидание |
|--------|----------|
| «PIN 1234» (без карты) | Не маскируется |
| «pin 1234» (без карты) | Не маскируется |
| «Карта 4111111111111111 PIN 1234» | Карта и PIN маскируются |
| «Карта 4111111111111111 pin 1234» | Карта и PIN маскируются |
| «карта 4111111111111111 PIN 1234» | Карта и PIN маскируются (смешанный RU/EN) |
| «4111111111111111 PIN 1234» | Номер без слова «карта» + PIN: оба маскируются (номер по Luhn, PIN рядом с картой) |
| «4111111111111111 пин-код 1234» | Номер без слова «карта» + пин-код: оба маскируются |

## Требования к реализации

1. Каждая ловушка должна быть представлена в `tests/data/*.csv` как negative
   кейс с `expected_masked=false` и пустым `expected_entities`.
2. Детектор не должен маскировать ловушку (иначе FP).
3. Ловушки добавляются в golden dataset и прогоняются через строгий harness.
4. Приоритет: ловушки из категорий 1 (исторические личности) и 2 (адреса
   организаций) — самые важные для критерия 3.3 и финалистов.
5. Опечатки и смешанные написания — positive кейсы: PII должна маскироваться
   даже при искажении служебных слов.
