# SECURITY.md — Обязательные правила безопасности и качества

Эти правила **нельзя нарушать** при любых новых правках. Каждая правка проходит
самопроверку по чек-листу в конце. Нарушение = блокировка мержа.

## 1. Логирование (абсолютный приоритет)

**Никогда не логируй:**
- исходные ПДН, значения, текст запроса/ответа;
- mapping (placeholder → значение);
- prompt, отправляемый в LLM;
- тело запроса целиком (кроме dev-режима `MOCK_LOG_REQUEST_BODY`).

**Разрешено логировать:**
- `pii_type`, `confidence`, `action` (masked/overlap_rejected/below_threshold);
- количество найденных ПДН, типы;
- `request_id`, `backend`, `status`, `latency_ms`;
- класс исключения (`type(exc).__name__`), **не** текст исключения.

**Правило:** если сомневаешься, содержит ли строка ПДН — не логируй её.
Используй `PIIDecision` для безопасных решений.

## 2. Валидация входных данных

- `/process` принимает `{payload: str, payload_id: str}`. Оба обязательны.
- Не приравнивай 100 000 токенов к фиксированному числу байтов. Ограничения
  `MAX_PAYLOAD_BYTES` и `MAX_ESTIMATED_TOKENS` задаются и тестируются отдельно для
  русского UTF-8 текста. Сверх лимита → понятная ошибка `4XX`, не падение.
- `payload_id` — строка, используемая как ключ корреляции. Не логируй его как
  секрет, но и не выводи в ответ без необходимости.
- Невалидный JSON, отсутствующее поле или неверный тип → `422` с безопасным сообщением,
  без входного текста и деталей стека. Это единое поведение FastAPI contract layer.

## 3. Хранение соответствия (mapping)

- Mapping живёт **только временно** внутри `PIIMasker.mask()` и удаляется после
  формирования masked. Для `/process` mapping в session не хранится: demasking
  выполняется возвратом сохранённого original.
- In-memory store ограничивается одновременно по числу sessions и приблизительному
  объёму байтов; при исчерпании лимита возвращается `429`, а не допускается OOM.
- Не пиши mapping на диск, в БД, в кэш без шифрования.
- Если добавляешь персистентное хранилище — только с шифрованием (AES-GCM) и
  ограничением времени жизни (TTL).
- Не возвращай mapping клиенту.

## 4. Ограничение доступа (allowlist)

- Сервис должен принимать запросы только от разрешённых систем-потребителей.
- Механизм: API-ключ в заголовке, allowlist по `X-System-ID`, или mTLS.
- На уровне демо достаточно: проверка `X-System-ID` против конфига.
- Неизвестная система → `403`, без раскрытия деталей.
- Исключение: проверочный `/process` вызывается без согласованных заголовков и использует
  default evaluation profile. Обязательная auth на этом endpoint сломает AlfaSonar;
  allowlist применяется к продуктовым интерфейсам и не должен блокировать checker.

## 5. Обработка ошибок

- Ошибки наружу — только безопасные сообщения: `409`, `410`, `422`, `429`, `502`.
- Не раскрывай стек-трейсы, внутренние пути, версии библиотек.
- При недоступности компонента (LLM, NER) — деградация: вернуть понятную
  ошибку, не падать с 500.
- `429` под нагрузкой — допустим, с `Retry-After`.

## 6. Зависимости

- Новая зависимость — только с обоснованием (зачем, альтернативы).
- NER-зависимости (`torch`, `transformers`) — только в optional-dependencies.
- Не добавляй зависимости, которые отправляют данные наружу (облачные NER/API).
- Локальный NER не должен отправлять пользовательский текст во внешние сервисы.

## 7. Конфигурация и секреты

- Секреты (ключи, токены) — только через переменные окружения, не в коде.
- `.env` — в `.gitignore`, не коммитить.
- Не логируй значения переменных окружения.
- Значения по умолчанию — безопасные (без реальных ключей).

## 8. Качество кода

- Все тесты проходят перед коммитом (`python -m pytest`).
- Типизация обязательна. Без `Any` там, где тип известен.
- Не дублируй логику маскирования/демаскирования/overlap — только через
  `app/pii.py`.
- Новый детектор → тесты: positive, negative, overlap, round-trip.

## 9. Чек-лист перед коммитом

- [ ] В логах нет ПДН, mapping, prompt, тела запроса.
- [ ] Входные данные валидируются (размер, формат).
- [ ] Byte/token limits проверены отдельно; store имеет entry/byte bounds.
- [ ] Mapping не пишется на диск без шифрования.
- [ ] Продуктовый доступ ограничен; `/process` доступен evaluation checker.
- [ ] Ошибки наружу безопасные (без стека).
- [ ] Нет новых зависимостей без обоснования.
- [ ] `pytest` проходит полностью.
- [ ] Нет дублирования PII-логики.
- [ ] Секреты не в коде, `.env` не коммитится.
